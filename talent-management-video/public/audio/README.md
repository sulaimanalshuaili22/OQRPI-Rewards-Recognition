# Audio assets

| File | Prop | What it is |
|------|------|------------|
| `music.mp3` | `musicFile` | Cinematic score generated by `tools/make-music.py` (three movements, hits on the key cuts, −18 LUFS). |
| `voiceover.mp3` | `voiceFile` | Narrator track generated by `tools/make-voiceover.py` with the Piper neural voice *en-US Ryan (high)*, placed at the exact caption timecodes and mastered to −16 LUFS. |

Both are wired in as the composition defaults, so a plain
`npx remotion render TalentManagement out/film.mp4` already has sound. The
film ducks the music to 38 % whenever the narrator speaks
(`src/voiceover-timing.json`).

## Replacing them with studio recordings

1. Record the narrator against `../../VOICEOVER-SCRIPT.md` — one file for the
   whole film, lines starting at the listed timecodes — and save it as
   `voiceover.mp3` here. Then update `src/voiceover-timing.json` with the
   start/end of each line (seconds) so the ducking follows the new read.
2. Drop the composer's track in as `music.mp3`.
3. Render with captions off: `--props='{"subtitles":false}'`.

## Regenerating the generated tracks

```bash
python3 -m venv .venv && .venv/bin/pip install numpy piper-tts
# voice model: en-us-ryan-high from https://github.com/rhasspy/piper/releases/tag/v0.0.2
.venv/bin/python tools/make-music.py public/audio/music.wav
.venv/bin/python tools/make-voiceover.py --piper .venv/bin/piper --model en-us-ryan-high.onnx --patch-captions
ffmpeg -i public/audio/music.wav -af loudnorm=I=-18:TP=-1.5:LRA=11 -b:a 256k public/audio/music.mp3
ffmpeg -i public/audio/voiceover.wav -af "highpass=f=80,acompressor=threshold=-18dB:ratio=2.5,loudnorm=I=-16:TP=-1.5:LRA=9" -ar 44100 -b:a 192k public/audio/voiceover.mp3
```

`--patch-captions` rewrites each caption's `from`/`to` frames in the scene
files so the on-screen text stays up exactly as long as the narrator speaks.
